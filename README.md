# RelayWatch

RelayWatch is a small, dependency-free command-line tool for checking a website's homepage and the contact or booking URL it should link to. Use it before publishing a site, in a scheduled maintenance job, or as a CI check.

It checks the HTTP response from both URLs and looks for a matching static link in the homepage HTML. It prints each finding and can return JSON and useful exit codes.

## Requirements

- Node.js 20 or newer.
- Network access to Cloudflare's DNS-over-HTTPS service and the websites being checked.
- Public HTTPS URLs you own or have permission to monitor.

No account, API key, subscription, or npm dependencies are needed. A check sends read-only GET requests to the destinations and their redirects. Domain names are sent to Cloudflare's public DNS resolver for destination validation.

## Quick start

Download or clone this repository, open a terminal in its folder, and run:

```sh
node src/cli.js check https://your-site.com/ https://your-site.com/contact
```

Replace both URLs with your own. Optionally install the local command with `npm link`, then run `relaywatch check ...`. This project is not currently published to npm; do not run `npm install relaywatch` expecting this code.

For multiple websites, copy `sites.example.json` to `sites.json`, replace the illustrative URLs, and run:

```sh
node src/cli.js check --config sites.json --json > report.json
```

Each config entry has `name`, `url`, and `contactUrl`. Up to 100 entries are processed sequentially. `--timeout 20` sets the timeout in seconds per URL, from 1 to 60. Run `node src/cli.js --help` for all options.

Exit codes are **0** when all checks pass, **1** when at least one HTTP failure is detected, and **2** for inconclusive checks or invalid input. A 401, 403, or 429 is inconclusive because an automated request may be blocked. If both failures and inconclusive findings exist, the exit code is 1; inspect the individual results for full detail.

For example, a CI job can run `node src/cli.js check --config sites.json --json` and treat a nonzero result as a prompt for human review. A scheduler can run the same command at a frequency you choose; RelayWatch itself does not install a scheduler or send alerts.

## What the results mean

Successful HTTP responses and a static link are useful signals, not proof that an enquiry reaches a person. RelayWatch **does not** run JavaScript, render a page, submit forms, complete bookings, test accessibility, confirm inbox delivery, or guarantee continuous uptime. A link missing from static HTML is inconclusive: it might be generated by JavaScript. Responses are point-in-time observations.

The tool checks up to five redirect steps and reads at most 256 KiB of successful HTML. It doesn't send credentials or cookies. Redirects to non-HTTPS, local IP addresses, internal domains, or custom ports are not followed. HTTP pages and localhost testing are intentionally unsupported.

## Security and privacy

Use this as a local tool with URLs you trust. DNS preflight does not pin the IP address used by the later connection. A hostname could change between validation and connection; **do not expose this checker to untrusted URL submissions or run it in a network with sensitive internal services without proper network isolation and egress controls**. Configuration files and exported reports may contain URLs and should be protected appropriately; do not put passwords, tokens, or private customer information in URLs.

## Development

```sh
npm test
```

The tests run without network access. Contributions that improve the checks, reporting, documentation, and tests are welcome. Before running real checks, obtain the relevant site's permission.
