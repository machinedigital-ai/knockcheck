# KnockCheck

KnockCheck is a small, dependency-free command-line tool for checking a website's homepage and the contact or booking URL it should link to. Use it before publishing a site, in a scheduled maintenance job, or as a CI check.

It checks the HTTP response from both URLs and looks for a matching static link in the homepage HTML. It prints each finding and can return JSON and useful exit codes.

## Requirements

- Node.js 20 or newer.
- DNS resolution and direct outbound HTTPS access to the websites being checked.
- Public HTTPS URLs you own or have permission to monitor.

No account, API key, subscription, or npm dependencies are needed. A check sends read-only GET requests to the destinations and their redirects. It uses your system's DNS resolver; it does not send a separate DNS request to a third-party web API.

## Quick start

Download or clone this repository, open a terminal in its folder, and run:

```sh
node src/cli.js check https://your-site.com/ https://your-site.com/contact
```

Replace both URLs with your own. Optionally install the local command with `npm link`, then run `knockcheck check ...`. This project is not currently published to npm; do not run `npm install knockcheck` expecting this code.

For multiple websites, copy `sites.example.json` to `sites.json`, replace the illustrative URLs, and run:

```sh
node src/cli.js check --config sites.json --json > report.json
```

Each config entry has `name`, `url`, and `contactUrl`. Up to 100 entries are processed sequentially. `--timeout 20` sets the timeout in seconds per URL, from 1 to 60. Run `node src/cli.js --help` for all options.

Exit codes are **0** when all checks pass, **1** when at least one HTTP failure is detected, and **2** for inconclusive checks or invalid input. A 401, 403, or 429 is inconclusive because an automated request may be blocked. If both failures and inconclusive findings exist, the exit code is 1; inspect the individual results for full detail.

For example, a CI job can run `node src/cli.js check --config sites.json --json` and treat a nonzero result as a prompt for human review. A scheduler can run the same command at a frequency you choose; KnockCheck itself does not install a scheduler or send alerts.

## What the results mean

Successful HTTP responses and a static link are useful signals, not proof that an enquiry reaches a person. KnockCheck **does not** run JavaScript, render a page, submit forms, complete bookings, test accessibility, confirm inbox delivery, or guarantee continuous uptime. A link missing from static HTML is inconclusive: it might be generated by JavaScript. Responses are point-in-time observations.

The tool checks up to five redirect steps and reads at most 256 KiB of successful HTML. It doesn't send credentials or cookies. Redirects to non-HTTPS, local IP addresses, internal domains, or custom ports are not followed. HTTP pages and localhost testing are intentionally unsupported.

## Security and privacy

Version 0.1.1 closes the DNS validation/connection gap present in 0.1.0. For every request, including each redirect, KnockCheck resolves the hostname, rejects the entire answer set if any address is non-public or malformed, and connects directly to one validated IP address. The HTTP client cannot resolve the hostname again. The original hostname is retained for SNI, the Host header, and certificate verification. Invalid certificates fail closed.

The transport uses a fresh, explicit HTTPS agent, disables environment proxies and connection reuse, accepts HTTPS on port 443 only, and never forwards caller cookies, authorization headers, or request options. DNS, connection, TLS and body reads share a per-page deadline. Response headers and inspected HTML are bounded; unexpected compressed content is rejected. Private, loopback, link-local/metadata, CGNAT, documentation, multicast, mapped IPv4, NAT64 and selected IPv6 transition ranges are rejected conservatively.

These controls address the identified SSRF/DNS-rebinding path. They are not an independent security audit or permission to scan arbitrary systems. If embedding the library in a public service, add authentication, rate limits, an appropriate destination allowlist, and network egress policy: a globally routable HTTPS address can still be sensitive, and deployment routing is outside this library's control. Keep configuration files and reports private, and do not put passwords, tokens, or private customer information in URLs. See [SECURITY.md](SECURITY.md).
